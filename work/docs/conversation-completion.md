# 对话与任务的完成判定

用户提交既可能是执行要求，也可能只是提问。普通问答的成功条件是经理完整答复并正常结束，不需要人为制造开发交付物。

| 本轮类型 | 示例 | 完成条件 |
| --- | --- | --- |
| `reply` 直接答复 | 你好、你是什么模型、如何使用此功能 | 引擎正常完成且存在完整最终答复；无需派工、文件、验证记录或 `team_complete` |
| `report` 审查与分析 | 审查代码、分析问题并给出建议 | 完整最终报告，或通过完成工具提交结论与检查依据；无需强制派工或写文件 |
| `files` 实际开发 | 修复错误、实现页面、保存报告文件 | 保留成员执行、真实文件及验证依据的验收条件 |

- 类型按当前用户要求在服务端判断。“如何实现”属于咨询；“能帮我实现吗”属于行动请求；混合要求中的明确开发动作优先。没有明确开发或分析要求时允许直接回复、澄清，不把角色模板当作用户开发授权。
- 续聊根据本轮文字重新判断，不因之前开发过就要求每次提问都交文件。简短“继续”沿用上轮类型，线程与团队快照沿用原有机制。
- 公开进度消息 `commentary`、空输出或尚未结束的消息不能算最终回复。自定义模型省略消息 `phase` 时，需要引擎完成事件、匹配的消息结束边界，且后面没有工具或其他工作事件。
- 已派发成员必须结束，最新一次执行成功，没有未解决反馈或待审批；经理的真实失败、取消也不因部分文字而变成成功。保持事件挂起/唤醒，不新增轮询或额外模型调用。
- 问答记录继续使用统一会话与轮次结构，结果增加 `mode: reply` 和完整 `reply` 正文；`summary` 用于通知摘要。主界面、历史、办公室和时序图显示答复完成。
- 历史自动修正仅限明确问答、原错误为文件验收未通过、引擎实际成功、存在完整答复且无成员阻塞的记录。保留原始 id、正文和时间；真正执行失败及开发未交付不会被修正。

验证覆盖普通问答、独立经理、自定义模型无 phase、混合开发请求、开发后续聊提问、空输出/失败/成员阻塞及历史修复幂等。`test-support/custom-model-engine-smoke.cjs` 使用真实本机 Codex 和本地模拟 Responses 验证完整链路，不请求用户付费模型。
