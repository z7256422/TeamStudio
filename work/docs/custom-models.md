# 自定义模型与分发清理（0.11.0）

## 需求与边界

允许用户配置多套模型服务，每套包含名称、Base URL、API Key、协议、默认模型和启用状态。团队及成员分别引用供应商 ID；同一团队可混用本机 Codex 和多个自定义模型。自定义模型继续由本机 Codex app-server 执行文件/命令、MCP、skills、指令、审批、中断、团队派发和成员反馈。

当前实现支持 **OpenAI Responses API 的 SSE 流式输出及函数工具调用**。仅提供 Chat Completions、Anthropic Messages 或其他协议的 URL 暂不能直接使用，应先使用支持 Responses 的服务/网关。连接测试验证指定模型的流式工具协议；模型执行质量、实际 MCP 服务权限仍需要用真实任务验证，不能把连通性测试等同于完整功能认证。

## 使用方式

1. 启动服务，在「接口与能力 → 自定义模型」添加连接。
2. 填写名称、准确模型 ID、Base URL，例如 `https://api.example.com/v1`，再填 API Key。本地无认证服务选择“无需密钥”。也接受以 `/responses` 结尾的完整地址，会自动规范为基础 URL；不自动猜测或补加 `/v1`。
3. 按供应商支持的值选择“思考强度”，再点击“测试连接与工具调用”，通过后保存。测试发送一个很小的模型请求，可能计费，不会执行模型返回的工具。
4. 在「Agent 配置 → 执行接口」选择该连接，模型填 `default` 可使用默认模型。成员与团队使用同一供应商时优先使用团队模型；不同供应商时使用各自连接的默认模型，避免把经理模型传给另一服务。
5. 保存团队更改后发起任务。修改团队默认供应商不会自动替换已有成员显式选择的供应商。

连接保存在服务端，保存立即生效；团队和成员的引用仍通过页面“保存更改”保存。团队导出仅包含供应商 ID、名称、类型和状态，不包含地址、模型连接认证或密钥。导入到另一机器时，需要迁移服务端连接目录或重新添加连接并调整成员引用。

## 凭据与续聊

- 服务端存储为数据目录中的 `providers.json`；Windows 使用当前用户 DPAPI 加密密钥，经固定 PowerShell 文件和标准输入处理，不把密钥拼入命令行。非 Windows 使用权限为 0600 的本地文件，密钥编码不等同于加密。
- 密钥不回传浏览器、不写入 localStorage、导出、运行历史或 Codex thread config。启动对应成员的 Codex 进程时通过专用环境变量传入；日志不转发自定义引擎原始 stdout/stderr，结构化事件对已知密钥脱敏。
- 编辑时 API Key 留空保留原值，输入新值轮换，选择无需密钥会清除原密钥。保存后旧进程被回收，下次执行使用新密钥。
- 模型配置写操作限本机同源页面；拒绝跨站 Origin 和非 loopback Host。不修改用户全局 Codex 配置。
- 思考强度为连接级执行参数，保存后影响下次新任务、派发及历史续聊，不改变供应商身份、模型或原线程。运行中仍禁止修改连接；新执行记录保存本次选择，旧执行记录不改写。用户修正不兼容强度后可以继续原任务。
- 任务接收时冻结团队成员的模型及接口指纹，续聊沿用原供应商、模型、团队和线程。修改连接名称、默认模型不会改变旧会话的模型；密钥轮换可用于旧会话。
- 若 URL、协议或认证方式发生变化，旧会话会要求恢复原连接或新建任务，避免把旧上下文静默发送到另一个服务。
- 使用中的连接不能修改/删除；更新期间新任务也不能抢用。历史仍引用的连接不能删除，但可停用；删除相应历史后可删除连接。删除连接后，浏览器保存的团队引用需要重新选择。
- 升级时停服，迁移 `.agent-manager/providers.json` 可保留连接 ID；同一 Windows 用户可继续解密。更换机器/系统用户后应重新填写密钥，不能只复制密文获得认证。

## 通用接口及模块边界

| 接口 | 用途 |
| --- | --- |
| `GET /api/providers` | 供应商目录、engine、协议、能力和公开配置 |
| `POST /api/providers/custom` | 新增连接 |
| `POST /api/providers/custom/:id` | 更新公开配置/凭据，留空密钥保留 |
| `DELETE /api/providers/custom/:id` | 删除无运行/历史引用的连接 |
| `POST /api/providers/test` | 测试表单配置；可携带 id 复用已保存密钥 |
| `POST /api/runs` | 统一执行接口，adapter 使用所选连接 ID |

供应商注册与存储在 `server/custom-providers.cjs`，凭据处理在 `server/provider-secrets.cjs` / `.ps1`，前端配置在 `components/CustomProviders.jsx`。注册目录区分 `id`、`kind`、`engine`、`protocol`、`capabilities`；未来其他 Agent 引擎可接入现有 runs/审批/事件契约，不必改变团队调度与页面结构。

Codex 通过 thread/start、thread/resume 的 `modelProvider`、`config` 临时覆盖接入，密钥使用 `env_key`。本次官方文档页获取返回 403，以工程协议快照和真实本机 Codex 联调核验支持范围；没有依赖未验证的 Chat Completions 原生支持。

等待继续沿用事件机制。新增模型目录通过共享 `/api/events` 的 `providers` 事件更新，没有定时查询。连接测试一次性 25 秒截止、可取消、不自动重试；失败分类显示认证、路径/模型、限流、流协议、超时和网络/TLS 信息，不回显上游原始错误正文。

## 思考强度兼容（0.12.2）

问题实例：GLM 连接的失败会话记录了 `xhigh`，上游报“不支持关闭思考；请使用 low、high 或 max”。旧版自定义连接未覆盖本机 Codex 的思考参数，因此可能把其他模型的档位带到此接口。报错本身不能证明发送了 `none`，也与面板展示/折叠思考摘要无关。

连接的公开配置新增 `reasoningEffort`：`default`、`low`、`medium`、`high`、`xhigh`、`max`、`minimal`、`none`。这些是可选参数值，不代表每个模型都支持全部档位；不按模型名称猜测或自动映射 `xhigh` 到 `max`。对应上述接口，应明确选 `low`、`high` 或 `max`，可先选 `low`。

- 缺少此字段的旧连接保持 `default`，不修改其他供应商的行为；编辑请求省略字段保留原值。`default` 表示不覆盖 Codex / 原会话设置，并非关闭思考。由显式档位改回 `default` 后，恢复旧线程仍可能沿用其上次设置，需明确选择档位才能覆盖。
- 显式值同时传给连接测试的 Responses `reasoning.effort`、Codex thread 配置 `model_reasoning_effort` 和每次 `turn/start.effort`，确保原线程里的旧强度也被覆盖。每个连接独立生效；不会用经理的强度覆盖其他供应商成员。
- `default` 模式的直接连接测试不指定强度，正式任务由引擎/会话决定；界面及测试结果对此作出说明，避免把连通性通过误解为所有执行参数均已验证。
- 思考强度与摘要是独立概念：前者控制模型计算配置，后者是模型可提供的公开摘要。选择 `none` 仅用于明确支持关闭思考的模型，不以关闭摘要来降低思考强度。
- HTTP 400/422 和 SSE 参数错误增加配置入口提示；上游错误正文限量读取，仅返回固定建议，保留密钥隔离。实际任务仍保留原报错及配置建议，不自动重试付费任务。

验收包含公开配置/持久化、旧记录兼容、编辑保留、非法参数、运行中修改保护、测试请求参数、错误脱敏，以及真实 Codex + 本机模拟接口的 low/high/max、成员隔离和原线程继续执行。未调用用户实际付费接口。

## 打包清理

`node work/package-portable.cjs` 生成新目录、ZIP 和 SHA-256，然后自动运行便携包启动烟测，成功后调用 `work/clean-packages.cjs` 清理旧版本。新包构建、校验或烟测失败时不清理旧版。

手动预览：`node work/clean-packages.cjs --dry-run`。
手动执行：`node work/clean-packages.cjs`。
指定保留版本：增加 `--keep Team-Studio-版本-windows-x64-时间戳`。

只处理 `dist` 中匹配本项目构建命名的旧产物；ZIP 必须有匹配的 SHA-256，程序目录必须与 manifest 完全一致。含 `.agent-manager` 数据、额外文件、修改文件或链接的旧目录保留并报告；不触碰开发数据目录、清理归档、用户工程或其他文件。不做任意路径递归删除。
