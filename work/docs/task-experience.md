# 任务对话、执行记录与通知（0.9）

## 交互约定

- 一次用户提交是一轮对话。经理派发、等待、验收以及成员返工属于该轮的执行记录，不增加轮数。一条任务可有多轮，每轮可有多次成员执行。
- 每轮展示用户要求、成员执行和最终交付。进行中展示成员状态快捷入口；执行卡片列出成员、派发来源、本轮执行次数、起止时间与耗时，公开进展、结果和操作按时间线排列。每位成员的「执行过程」及每条操作的详情默认折叠，可独立展开；折叠时保留成员状态、审批入口和操作数量，单条操作保留类型、状态、时间及简短命令预览。事件同步更新不重置用户的展开选择，新任务对话与历史记录共用此交互。已结束轮次默认折叠成员明细，交付结果保持可见。
- 公开进展只展示成员公开回复、执行阶段、命令、工具调用、文件修改及结果，不展示内部推理。新消息按 item ID 保留边界、阶段与时间；旧版合并输出标明缺少边界，不猜测消息时间或最终结论。
- 操作记录保留最近 40 项，可按项展开命令和结果。对话默认读取最近 50 次执行，可按需加载更早记录（最多 2,000 次）；轮数、成员次数和交付摘要按全部记录计算。
- 侧栏新任务下方显示最近 6 条任务，跨页面同步状态，点击恢复原对话。其余记录仍可在历史界面查看。
- 办公室状态跟随当前任务的 `taskId`。点击“新任务”后清除上一任务的本地状态并显示待命；恢复历史对话后只显示该任务的成员运行和派发状态，不能用全局最近运行覆盖当前任务。
- 新任务输入区可选工作区可写 / 只读，仅覆盖该任务；保存到服务端运行设置后由成员和续聊继承，不改写团队默认值。

## 时序交互图

- 历史会话详情右上角的「时序交互图」打开独立查看窗口。保持现有页面风格，按轮次、记录时间展示用户需求、真实派发、成员返回和验收交付；返工沿用所属轮次并标记执行次数。
- 默认只看核心交互，可按轮次和参与者筛选、切换「显示执行细节」、缩放和横向浏览。命令、工具及公开进展以成员自身的回环表示；返回与交付使用虚线。每段最多 80 条，可翻段查看所有已加载事件。
- 点击箭头或通过键盘 Enter / 空格查看完整输入、输出、起止时间、退出码、文件与验证信息。运行中的会话每 4 秒更新，结束后可手动刷新；关闭窗口释放定时器并忽略未完成请求的结果。
- 关系只来自统一运行契约的 coordinatorRunId、source、handoffFrom 和会话消息 runId，不分析自然语言猜测接收者。返回箭头表示结果按派发关系就绪，时间为执行结束时间，不代表对方实际读取时间。广播保留团队频道节点；不关联 runId 的全局频道消息不混入任务。
- 使用现有会话读取接口（最多最近 2,000 次执行），不修改历史库。旧记录的逐条消息边界、早期工具明细和未持久化的频道消息无法凭空恢复；缺少时间不使用更新时间替代，达到保留上限或加载不完整时提供说明。
- `runtime/interaction-sequence.js` 负责无供应商依赖的数据投影和筛选，`state/useInteractionSequence.js` 负责读取，`components/InteractionSequenceDialog.jsx` 与 `styles/interaction-sequence.css` 负责展示。投影行为测试：`node --test work/panel-src/runtime/interaction-sequence.test.cjs`。

## 审批与交付提醒

右上角消息中心提供未处理数量和短暂提示，不自动打开面板、不抢焦点。待审批显示成员、任务、具体事务、命令、目录、文件及网络权限范围；同一请求可在消息中心、所属执行卡片或办公室成员详情确认。全局提交锁防止在多个入口重复提交，失败保留请求并显示错误。

交付通知由持久化运行记录投影得到：经理验收并结束后才生成；成员完成、只输出计划或经理仍在执行不会生成交付通知。每轮通知 ID 固定，续聊交付生成下一轮通知；关闭页面期间完成的结果重新打开后也能读取。已读和清除状态按通知 ID 保存在当前浏览器，并同步到同源其他标签页，历史删除后相应通知也消失。

消息中心支持单条清除、清除已读、清空交付，以及撤销最近一批清除。清除只移出通知列表，事件同步和刷新不会恢复已清除的旧通知；新的轮次仍正常提醒。待审批请求不参与通知清除，任务历史和交付记录不删除。状态保存失败时明确提示当前页面已生效、刷新可能恢复，不用后台事件同步成功覆盖此提示。

普通并行 / 接力新任务使用 expectedAgentIds 防止队列尚未启动下一人时过早通知。旧记录缺少这份名单时不推断整队交付。

成员已经完成后，经理仍可再次 team_dispatch 给该成员修正，复用同任务中的原线程。其他成员通过结果向经理报告问题，由经理安排返工；普通成员没有越过经理派发他人的权限。整轮已验收后，可在同一对话提交修改要求，开始新一轮。

## 实现边界与验证

- server/conversation-rounds.cjs：用户轮次归组、旧记录兼容、执行次数与交付通知；新数据用 context.roundId，旧数据优先使用 coordinatorRunId。
- shared/run-activity.js：公开回复投影与时间边界；run-store 持久化 messages。
- API /api/conversations 的 turnCount 是用户轮数，executionCount 是运行次数；/conversation 保留 total（执行数），新增 rounds 和 limit 参数；/api/notifications 返回交付消息。
- panel-src/components/ExecutionCard.jsx：轮次、成员执行与交付结果；runtime/conversation-model.js：展示投影；state/useNotifications.js 与 NotificationCenter.jsx：跨页面通知。
- 自动检查包括旧数据归组、经理返工、消息边界与持久化、审批范围、交付去重、未启动队列防误报和只读权限继承。浏览器夹具使用 test-support/team-fixture.cjs（33212），不会调用真实模型；目标含「审批」时逐个成员请求确认，用于检查三个审批入口。
