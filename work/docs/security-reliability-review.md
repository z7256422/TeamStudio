# 控制平面安全与可靠性审查

核实与修复日期：2026-09-23。对应发布版本以 `server/app-info.cjs` 为准。

## 逐项结论

| 反馈 | 核实结论 | 修复 |
| --- | --- | --- |
| P0 跨域策略全开 | 成立。原 JSON、SSE、OPTIONS 返回 `*`，部分本机接口才单独检查来源；回环监听不能阻止网页访问 | 所有路由入口统一验证同源 Origin、回环 Host/端口和 Fetch Metadata；拒绝 null Origin、外站、Host 重绑定，移除 `*`；设置禁止嵌入与跨站资源策略 |

| 审批超时、失败和重启无通知 | 成立。原审批虽超时终止，但没有完整用户通知 | 卡片显示截止时间，超时持久记录具体事务；失败、取消与重启中断投影到通知中心 |

| 历史高频全量重取 | 成立。已有事件通知，但收到通知后仍取全部详情 | 轻量分页，每页默认 20 次执行；版本增量只返回变更运行，未展开不取正文；展开与时序图读取预览，全文下载保留 |

| 文档与版本号脱节 | 成立。API 表缺漏，状态同步和队列说明仍写旧行为 | 更新完整 API 表、同源入口、事件同步、队列、轻量读取与诊断语义；运行与打包版本统一引用 `app-info.cjs` |

## 行为与兼容边界

- 用户配置、历史和自定义连接不被覆盖。旧完整 API 保留；新界面使用 `view=compact`，裁剪只影响预览，不修改完整公开消息。
- 必须通过本机服务地址使用管理功能。`file:` 与不可信 sandbox iframe 都可能使用 `Origin: null`，因此不设置 null Origin 例外；文件入口提供旧配置导出。localhost 与 127.0.0.1 也不是同一 Origin，应在同一个地址打开页面和 API。
- 来源防护针对恶意网页。本机原生客户端没有 Origin 时可访问，当前服务没有新增登录、访问令牌或本机进程隔离。
- 浏览器关闭不影响任何新队列；服务进程停止/重启会明确中断，不自动重放已有动作。经理续聊恢复团队快照；非经理续聊仍恢复原成员，不能假装已补做全部未执行成员。旧版缺失席位显示未完成。
- 调度及成员等待仍是挂起/事件唤醒。SSE 保活、250ms 事件合并、800ms 写盘合并、UI 耗时时钟和明确超时不承担定时派工或循环查询。
- 进程未知异常采用受控退出，不在可能损坏的状态下继续接任务；没有新增系统守护或自动重启服务。再次启动后能看到已保存的中断通知。
- 页面预览保留最近消息与部分正文，可下载完整已保存记录。事件和操作本来就是有限窗口，不能补回旧版本已经删除的内容；公开分析摘要受原有保存上限约束。
- 引擎/认证检查不等于远程模型可用；自定义模型需显式点击测试连接（会请求供应商接口）。自动传输测试使用本机模拟模型，不能证明真实模型质量、外部 MCP 服务或全部认证环境均通过。

## 模块与测试

新增后端职责模块：`local-access.cjs`（来源边界）、`sse.cjs`（连接隔离）、`task-queue.cjs`（持久席位调度）、`run-alerts.cjs`（故障通知）、`history-view.cjs`（轻量快照）、`engine-readiness.cjs`（引擎/认证检查）。沿用统一 provider-neutral HTTP/SSE 及运行契约。

测试命令：`npm test`。发布入口 `npm run package` 强制要求真实 Codex 可启动，运行全部自动测试、构建、校验 Node 官方签名摘要和实际解压包烟测；成功后只清理无用户数据的旧构建。

本轮自动测试覆盖来源伪造与真实未决审批、无浏览器接力、并发限制、失败/停止传播、SQLite 重启中断、历史分页/版本增量/全文下载、SSE 故障/背压、审批超时通知、进程退出与引擎认证。真实引擎用临时 CODEX_HOME、临时目录、本机 Responses 服务验证团队派发、等待、长中文成果分段无损读取和验收，不触碰用户项目及模型服务。

浏览器回归使用独立 33212 端口的生产路由 + 假引擎：提交 4 人接力后刷新、恢复最近会话、展开执行预览、检查全文入口、交付通知和时序图。开发机原 3210 服务未停止或升级，不将源码完成等同于运行实例已生效。
