# 历史续聊与办公室需求（0.6.0）

## 历史连续对话

- 入口：新任务 → 选择历史对话；或运行记录 → 历史记录 → 在主界面继续。历史详情仍可直接续聊。
- 保留所选记录的成员、供应商、工作目录和原执行设置，恢复其原会话，不误用该成员后来创建的会话。
- 后续要求在原会话内增加轮次，历史列表始终只占一条，标题保留最初任务，状态和时间更新。底层按轮保留数据，同会话展示用户要求、成员回复、轮次、时间、状态和步骤。
- 删除和清空按整会话处理；任一轮运行中或待审批时，完整保留所有轮次。
- 主界面显示原配置，只在发送后开始执行；办公室定位原成员并同步真实状态，支持返回对话，历史成员工位不修改团队配置。
- 始终续接原会话的最新上下文；从旧轮次进入不代表创建分支或回退。只续聊该成员，不隐式重跑整个团队。
- 运行中禁止重复发送，支持停止及提前编辑下一条要求；失败保留草稿。离开页面不取消后端执行。
- 运行记录落盘，刷新页面或重启服务后仍可查找。重启中断的活动记录不伪装为仍在执行，保留原 thread 供用户继续。
- 兼容原有创建运行、审批及会话 API；新历史会话 API 使用通用 HTTP 契约，Codex 协议转换留在后端。

## 办公室

- 导航和标题统一为“办公室”，保留像素画风。
- 以真实工作场景为主，通过人物动作、道具、图标、文字和工位背景共同区分状态。
- 待命喝咖啡、排队等候、启动就位；分析时思考、执行命令时打字、搜索时读书、编辑时搭建、回复时整理交付。
- 审批举牌、重试调整工具、断线显示信号；完成庆祝、失败求助、取消后休息。
- 人物外观按成员 ID 稳定生成，休息区增加小猫。装饰动作不产生虚构任务、百分比或状态。
- 保留点击成员查看任务来源、上下级接力、工作目录、开始时间、运行时长及步骤的能力。
- 动画开关记住偏好，系统减少动态效果时停止动画；断线冻结动作并标记旧数据。无动画时仍能识别状态。

## 验收

1. 连续追问两轮，thread、目录和指令保持一致；历史条目数量不增加，主界面可恢复前后对话。
2. 重复提交被拒绝；停止后可继续；失败草稿保留；不同轮次事件不串线。
3. 重开存储后仍有历史及输出，删除后不复活，未结束记录明确中断。
4. 多团队办公室可筛选，工作、审批、失败、完成和空闲均有明显不同表现；手机布局可用。
5. 动画开关持久有效，断线不展示虚假活动，浏览器无未处理错误。

## 本次验证

- 48 项自动化测试通过，前端离线 HTML 构建通过；涵盖先聚合再分页、活动会话完整保留、整会话删除与原配置继承。
- 隔离浏览器验证主界面选择历史、连续追问后列表数量不变、办公室实时状态与返回对话、整会话删除及手机布局；执行引擎使用假客户端。
- 本机服务已升级至 0.6.0，现有两轮真实记录合并显示为一个会话；逐项核对输出、事件数量和 thread ID，主界面成功恢复两轮对话。未向用户原任务发送测试要求。
