# 成员成果的完整交接

## 行为

成员公开回复按消息保存，最终正文不再受旧的 10 万字符截取限制。负责人接收成果时，`team_wait` 只携带状态、短预览、成果运行编号与长度，使用 `team_read_result` 按需读取正文。进展与最终成果分开；没有消息边界的旧记录明确标为 `legacy-mixed-output`，不能视为已知完整的最终成果。

`team_wait` 已通知过的成员仍可重复读取全文。发现预览不完整时先读取已保存的内容，只有成果实际存在问题才派发返工。部门负责人和总负责人使用同一规则，不能越过直属交接边界读取孙团队或其他任务。

## 工具契约

- `team_wait({cursor?})`：无 cursor 时沿用事件挂起/唤醒，完成、审批或成员反馈触发返回；没有轮询或周期超时。`members[].output` 是短预览，`outputTruncated` 表示有更多正文，`result` 给出 `runId`、`source`、`ready` 和 `totalChars`。`outputUnchanged` 只表示状态已通知，不限制全文读取。
- 等待响应的 `hasMore` / `nextCursor` 用于读取同一次唤醒的其他状态页。`pending` 始终表示所有直属运行中是否仍有活动任务，而非仅当前页。只将已发送的成员页标为已通知。重新开始一次无 cursor 的等待会替换缓存快照，旧 cursor 显式报错；分页不等待新事件。
- `team_read_result({runId, section?, cursor?, maxBytes?})`：默认 `section=result`，返回 `content`、`source`、`offset`、`totalChars`、`hasMore`、`nextCursor` 与运行状态。`progress` 读取保留的公开进展；`feedback` 读取该成员向其上级提出的反馈原文；`error` 读取错误原文。长问题在等待响应中给出 `truncated` 和 `details`，需读完再答复。
- `hasMore=true` 时，将 `nextCursor` 原样传给同一个工具、同一 `runId` 和 `section`；`hasMore=false` 表示当前文档已读完。成果 cursor 绑定内容版本；重复读取幂等，内容变化、串用、越界或非法参数会明确报错，不拼接不同版本的正文。分段依据 UTF-16 位置，但不会切开 emoji 的代理对。
- 等待和成果读取的**整个序列化 JSON**最多 6,000 UTF-8 字节，计入中文、多字节字符、JSON 转义、元数据和 cursor。读取可用 `maxBytes` 调小至 1,024 字节，适配更低的工具输出限额。本机当前 Codex 的默认传输验证使用该上限；其他引擎若设置更低预算仍需匹配适配器限额。

最终成果优先取已结束的 `final_answer`；无 phase 的模型取终态下最后一条已结束的非 commentary 消息，随后才使用明确提交的交付数据或标记为旧格式的输出。仍在运行的记录不冒充已交付，只有进度消息不会变成成果。文件验收、成员失败和审批约束保持原规则。

## 历史与兼容

正文复用运行历史的 SQLite 持久化，不生成额外任务、派工或历史轮次。负责人续聊可读取同任务、自己祖先运行直接派发的成员成果；当前分支、同任务及直属权限均需满足。

团队工具协议升级为版本 2。Codex 不能在恢复线程时新增动态工具，因此旧线程首次续聊会在原任务下进行已有的兼容迁移，注册新工具，并携带近期公开记录和最近 20 条直属成员成果编号。原运行历史保留，新协议线程正常恢复；已被旧版本从历史正文中删除的文字不会自动恢复。运行中的旧服务和旧线程不会被热替换，需使用更新后的服务续聊或创建任务。

## 验证

覆盖长中文/emoji/转义文本逐字拼接、多成员状态分页、重复读取、未取页面的通知标记、跨任务与跨层拒绝、续聊历史读取、失效 cursor、长问题、失败信息、空结果，以及超过旧存储长度限制的成果重启读取。原有反馈、取消、等待挂起和逐级交付测试一并回归。
