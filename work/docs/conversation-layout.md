# 对话记录排版（0.11.1）

根据用户提供的参考图调整执行记录布局，沿用工作台原有浅色、紫色强调、字号体系和控件，不复制参考图的深色风格。新任务恢复会话与历史记录共用 `ExecutionTranscript`，不改变运行协议、轮次、成员归属、权限或历史存储。

- 公开进展和最终结果按时间直接展示正文，附简洁的类型与时间；移除执行记录的竖线、圆点及每条命令独占两行的排版。
- 相邻命令归为一组，默认折叠；公开进展、文件修改和其他工具调用会分隔命令组，不跨阶段合并。
- 单条命令只需一次展开；命令组展开后可分别查看每条操作。摘要呈现图标、简短状态、命令和紧邻的展开箭头。
- 展开详情使用现有浅色面板：上方 Shell/工具名称，中间完整命令与输出，下方开始时间、结束时间、退出码或执行状态。长输出内部滚动，不撑宽对话区；失败始终有明确文字提示。
- 摘要简化常见 PowerShell 启动包装，详情保留完整命令。正文不设内部滚动，保留原公开回复，旧合并输出仍标明来源且不伪造时间。
- 历史“成员执行”和“执行过程”默认折叠，运行中的“成员执行”首次加载时展开。事件更新与任务完成均不重置展开状态，单条命令发展成命令组时保留已打开的详情；没有新增轮询。
- 操作与进展计数明确标注“本次执行”，不是成员累计。再次派发或返工单独成卡，提供“查看上次执行”入口，定位并展开同轮该成员上一次执行的过程；较早执行尚未加载时提示加载更早记录。

模块：`panel-src/runtime/execution-transcript.js` 负责顺序与分组，`components/ExecutionTranscript.jsx` 负责展示，`styles/execution-transcript.css` 负责布局。

验证：分组/旧历史/命令摘要行为测试，离线构建，以及 `node work/test-support/transcript-fixture.cjs` 的 33214 隔离浏览器验证。夹具只使用内存记录和生产读取/SSE 路由，禁止启动引擎或修改真实历史。

## 0.11.2 层级调整

“执行过程”使用独立标题栏，展开时采用已有浅紫色强调。正文相对标题内缩并添加区域边线；命令组内的单条命令与输出面板逐级缩进，输出面板进一步区分标题、内容和状态区域。边线仅标明父子归属，不恢复逐条圆点时间线。桌面和窄屏分别验证，折叠行为及执行数据不变。

## Markdown 正文（0.13.2）

- 用户要求、成员公开进展/回复、历史输出、思考摘要、交付报告和成员问答共用 `MarkdownContent`；原始记录不变，已有历史打开即生效。
- 支持标题、粗体/斜体/删除线、行内代码、代码块、嵌套列表、只读任务清单、引用、分隔线、表格与外部链接。普通文本保留换行，流式内容按已收到的文本逐步渲染，未闭合代码块也可阅读。
- 复用浅色紫色风格；代码块、宽表格内部横向滚动，不撑宽对话区域。工具命令与输出仍按原始文本展示，避免改变日志含义。
- 离线打包 markdown-it；关闭原始 HTML，限制链接协议，外部链接新窗口打开且隔离 opener；图片显示为手动打开的链接。工作目录/相对路径保持可阅读，不误跳到面板路由。
- `MarkdownContent` 对未改变的正文复用渲染结果。消息增量不更换组件 key，不改变上一版的手动折叠与完成后保持展开行为；不增加轮询或模型请求。
