# 流式思考摘要（0.12.0）

## 需求与交互

- 新任务和恢复/历史对话中，每位成员的每次执行都有独立的“思考摘要”区域，位于状态下方，不藏在默认折叠的“执行过程”内。保持现有浅色和紫色控件风格。
- 只展示执行引擎公开提供的 reasoning summary；不请求、展示或保存原始推理、reasoning content/text、加密推理内容。摘要不作为正文、最终答复或交付凭据。
- 分析阶段开始后自动展开，摘要逐段追加。分析结束、开始调用工具/输出回复或执行终止后保持当前展开状态，用户仍可点击标题展开或收起。用户手动收起后，同一阶段的增量不会重新展开；进入新的分析阶段时自动展开一次。
- 多次分析标明段号、开始/结束时间；标题持续显示状态和最近活动时间。摘要为空时如实提示等待或“本次分析未提供可展示的摘要”，不编造进度或摘要。长摘要内部滚动，用户上滚阅读时不抢滚动位置；支持键盘操作和减少动画偏好。
- 断线显示连接恢复状态，不把旧内容当成新进展；重连通过原有事件机制补快照。失败/停止/服务重启后保留已收到内容和当前展开状态，未结束分析标记中断。重新打开历史时默认折叠，续聊与成员返工不串入上次执行。
- 不改变用户轮次、派发机制、团队配置或文件权限；不增加轮询、模型调用或额外 agent。自定义 Responses 模型通过本机 Codex 返回摘要时同样可显示；摘要生成能力和详细程度沿用引擎/模型配置，不强制不兼容的参数。

## 接口与实现

Codex 已生成的本机协议为依据：`ReasoningSummaryTextDeltaNotification`（itemId、threadId、turnId、summaryIndex、delta）、`ReasoningSummaryPartAddedNotification`，以及 reasoning item 的 summary 数组。只映射 summary 白名单事件，忽略原始 reasoning/textDelta 和旧版原始推理通知。

- `server/codex-reasoning.cjs`：适配和过滤；将摘要转换为通用 `reasoning_summary` 事件，stage 为 started / part / delta / completed；递归清理 turn/thread 快照内的原始推理字段。
- `shared/run-reasoning.js`：不可变投影，按 itemId 与 summaryIndex 合并；完成快照覆盖增量，序列去重，限制迟到事件影响。结果保存在原有 `progress.reasoningSummaries` 中，随详情 API、SSE 和 SQLite 历史提供。
- 每次执行保留最近 40 段，每段最多 32 个片段、20,000 字符，总计不超过 120,000 字符；超过单段上限明确提示，段号保留实际顺序。摘要独立于最近 200 条原始事件的缓冲。
- `ExecutionReasoning.jsx` 与独立 CSS：新分析阶段自动展开，结束与增量更新不重置手动选择；新任务与历史复用。外层 `ConversationRound` 不因运行结束更换 key 或强制收起，避免重建摘要组件。数据继续使用共享 `/api/events` 的变更通知；单执行 SSE 消费者支持通用摘要事件。
- 旧记录没有保存摘要时不伪造补全；读取旧事件时清理原始推理。新增数据位于现有 progress 字段，无需破坏性数据库迁移。

## 验收

覆盖分段增量、完成快照去重、跨执行隔离、非法索引/长度、迟到事件、结束/停止/失败/重启收敛与原始内容过滤。用隔离服务验证 SSE 流式渲染、手动折叠保持、完成后保持展开、新分析阶段展开、无摘要、断线、窄屏和历史恢复；真实 Codex + 本机模拟 Responses 验证协议转发，不调用付费模型或操作用户历史。
