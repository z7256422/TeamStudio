# 挂起等待与事件唤醒

## 需求与边界

- 经理等成员、成员等答复、用户审批及界面状态同步都不能靠固定间隔检查推进。
- 等待中的工具保留原 Promise、运行与引擎 turn；结果到达后恢复原调用，不创建新轮次，不因时间流逝重复调用模型。
- 停止、失败、断线重连、页面切换和服务重启有明确收尾；不能遗漏最后状态或把旧会话响应写进新会话。
- 保留必要的一次性截止与连接保活，它们不承担业务状态查询，不自动重新派发任务。

## 调度

`team_wait` 不再每 120 秒返回。存在活动成员且没有新结果时挂起，由直属成员完成/失败、审批变化、提问/反馈结束或经理停止唤醒。按经理索引等待者，普通文本输出不触发调度唤醒。注册等待者后立即检查状态，覆盖注册期间的变化。

`team_ask_manager` 保留原工具调用，`team_reply_member` 直接结束等待并返回答复。取消和引擎异常释放等待。团队挂起工具不使用通用审批的 10 分钟期限；反馈仍保留一次性的 5 分钟未答复截止，期限到达返回阻塞，不能自动重试或冒充已完成。

## 界面与通用协议

- 新增 `GET /api/events` SSE，供应商无关。`ready` 表示新连接/重连，需要补快照；`change` 携带 `topics` 与变更运行的 `runId / taskId / conversationKey`。
- 聊天、执行面板、历史/最近记录、办公室、审批、通知、成员消息和诊断共用页面级事件连接。初次读取后挂起，相关事件到达才读相应现有 HTTP 快照接口。
- 同路径订阅共享一次请求；读取中收到变化合并为一次后续读取。不同任务的事件不会刷新当前任务。退订最后一个消费者时中断请求并释放连接，迟到响应不更新页面。
- 服务端只在有变更后启动一次 250ms 批量发送，用于合并文字增量；空闲时没有状态查询或批处理循环。审批详情晚到、删除历史、环境修复完成也发布事件。
- 运行输出继续使用原有运行 SSE，连接时新增 `snapshot` 权威状态；即使终态事件离开回放窗口，重连也能完成收敛，取消原来的 5 秒 HTTP 兜底查询。
- 断线期间显示同步错误，EventSource 负责连接恢复；每次重连或浏览器网络恢复事件补快照，包括服务重启后的中断状态。HTTP 失败不循环重试，后续变更、重连、网络恢复或用户刷新会再次读取。
- 慢客户端输出积压超过上限时断开连接，重连后读取最新快照，避免内存无限增长。

## 保留的定时行为

仅保留 SSE 15 秒连接心跳、本地运行时长显示、提示自动消失、请求/审批/反馈的一次性截止，以及有写入时才安排的存储合并。这些不会轮询成员状态，也不会周期唤醒模型。

## 验收

自动测试覆盖挂起一小时不自行返回、普通输出不唤醒、取消释放、审批/反馈恢复、定向订阅、同路径共享、空闲零查询、慢请求变化合并、迟到响应丢弃、重连补快照、慢连接回收和终态快照收敛。浏览器另验证等待期间零状态查询、反馈后聊天/办公室/通知更新及会话切换。
