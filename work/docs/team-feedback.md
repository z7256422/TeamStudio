# 成员向项目经理反馈

## 目标与范围

项目经理主导模式中，成员遇到接口约定、需求歧义、实现取舍或阻塞时，能够提问并取得经理决定后继续当前工作。普通进度仍通过执行记录展示，权限审批继续由用户处理，经理答复不能替代授权。

## 交互规则

1. 成员调用 `team_ask_manager(question, context?)`，说明具体疑问、已完成工作和已尝试方案。每位成员同时只有一个待答问题。
2. 此工具保持等待，成员原运行和原 Codex turn 不结束。办公室显示“等待经理答复”，不会新建历史条目或增加用户对话轮次。
3. 项目经理的 `team_wait` 被提问唤醒，返回问题 ID、成员、问题、背景和提问时间。经理正在处理其他工作时，问题保留到下一次 `team_wait`；不抢断经理正在执行的命令。
4. 经理用 `team_reply_member(requestId, answer)` 回复明确决定。答复通过原工具调用返回成员，成员继续原上下文。经理无法解决时应说明阻塞和下一步，不得臆造用户要求。
5. 未回复问题不会因为经理读过一次就消失；再次等待会继续返回待答问题。经理可回复多个成员的问题，等待答复的成员仍占执行席位，避免绕过并发限制。
6. 5 分钟没有答复时问题标为超时，向经理和用户发出提示，返回明确阻塞结果。成员不得依据猜测继续依赖此答案的工作；经理需在成员结束后重新派发处理，超时不能算作已答复或通过验收。
7. 停止成员、停止经理、引擎失败或服务重启会结束相关等待，保留提问记录和取消原因。重复调用和重复回复不得产生多份答复；其他任务不能回答本任务的问题。

等待与继续使用挂起/事件唤醒，经理不再周期性超时重试。界面同步也使用事件通知；一次性超时及断线恢复详见 [挂起等待与事件唤醒](event-driven-execution.md)。

## 可视化与历史

- 聊天执行卡片和办公室详情显示提问、补充背景、答复、状态、双方身份及时间，历史记录默认折叠已结束的问答。
- 时序图显示“成员 → 经理：提问”和“经理 → 成员：答复”，同一问题只显示一次，不伪造取消为经理答复。
- 右上角消息中心显示反馈超时通知，普通提问由经理自动处理，无须用户逐条点击确认。
- 问答数据随运行记录持久化，与普通手工成员消息区分；清除通知不删除问答。

## 引擎与兼容

协调器使用供应商无关的反馈数据和工具契约，Codex adapter 负责映射动态工具请求/返回。成员只有提问工具，经理拥有答复工具，成员不能自行派工。新任务、返工和续聊使用同一协议。

本机 Codex 的 `thread/resume` 不支持补充动态工具。旧版本创建的引擎线程在首次续聊或再次派工时，会在原任务记录内建立支持新工具的线程，并带入已有任务要求和面板保存的近期公开输出；原历史保留。页面明确显示这次兼容迁移，不宣称恢复了旧线程完整的引擎内部上下文。新协议创建的线程正常恢复原 thread。

## 验收

覆盖真实工具请求/返回、等待唤醒、重复等待、双成员并发、重复请求、跨任务拒绝、空内容、超时、取消、服务重启、反馈后返工/续聊、权限不变，以及聊天、办公室和时序图的状态一致性。
